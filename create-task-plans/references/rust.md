# Rust 任务的构建、缓存与验证

仅当当前任务实际涉及 Rust/Cargo 构建、测试或相关脚本时读取。纯文档、Python、前端或其它不调用 Cargo 的任务不需要套用本节；混合项目按当前任务涉及的部分选择。

## 先识别项目能力

读取目标 crate/workspace 的 Cargo.toml、Cargo 配置、仓库协议及 CI，确认具体包、目标、features、工具链与聚焦测试。仓库专用约定优先；没有明确依据不更改 profile、编译 flags、features 或工具链来换取速度。

- **只有原生 Cargo**：使用项目原有构建与缓存路径，写入可直接执行的聚焦命令；不因存在 Rust 就假定有 Python、槽位脚本或 Relax。
- **已有槽位入口**：检查脚本存在、解释器可用、参数及继承规则，再使用该入口；同阶段顺序检查一次调用，子命令复用同一槽位，不重复手工领槽。
- **已有 Relax 等加速入口**：另外检查 alias/运行器和目标测试兼容性。已验证路径用常驻测试迭代；未知路径安排有界探针，失败或无结果后回到原生 Cargo。不能将 Rust 与 Relax 视为同时具备的能力，不为普通任务自动安装它。

## 20 个共享槽位

仓库已经规定槽位池或用户要求使用共享槽位时，将以下契约写入任务。已有仓库入口负责实现这些操作；不存在入口时可按实际平台使用原子目录操作手工实现，不依赖 Python。仓库尚无槽位需求时沿用原有缓存，不为任务无故建立另一套池；已指定不同容量或布局时遵守项目约定。

1. 默认共享池为仓库的 `target/rust-slot-1` 至 `target/rust-slot-20`，所有计划共用，不按任务编号固定分配、不创建任务专属缓存。
2. 用原子目录创建领取 `target/rust-slot-locks/slot-N.lock`，仅成功者持有；占用时尝试下一个，全部占用时等待。不删除未确认已停止的其它持有者锁。
3. 记录真实持有进程 PID 与任务/会话信息，持有进程覆盖整个构建与验证阶段。不要记录一个即将退出的临时 shell PID 后留下孤立锁。
4. `CARGO_TARGET_DIR` 和 `CARGO_BUILD_BUILD_DIR` 设置为同一槽位的绝对路径，所有构建、检查、测试及间接调用 Cargo 的子进程继承；不通过额外配置或 target-dir 参数绕过。
5. 同阶段复用同一槽位；应用、常驻测试及其它使用产物的子进程停止后才释放。正常、失败与中断均覆盖清理，只删除自有锁，保留编译缓存。
6. 槽位隔离不能解除共享源码、依赖、验收资源和 CPU/内存预算限制。20 个槽位不是并发启动 20 个重型编译的要求。
7. 验收记录槽位、两个绝对目录、确切命令、退出码和有效测试数量；编译成功或零测试不能替代行为验收。

## 快反馈与完成验收

- 在任务中写明运行目录、包、目标、features、非空测试过滤条件与成功信号。聚焦过滤减少执行范围，但不保证减少整个 Rust 测试目标的编译成本。
- 若实际存在且兼容的常驻测试工具，函数体等受支持改动可保持同一会话，读取本次修改后的新 verdict，确认运行数大于零及预期失败/通过数。预期断言失败是有效红灯，旧通过结果不是当前修改的证据。
- 签名、类型布局、trait、宏、依赖或 features 变化时，按工具能力重新启动并执行原生聚焦验证；不把热改测试推广为所有编辑都兼容。
- 完成验收继续执行仓库要求的原生测试、Clippy、真实渲染及实机检查。格式化遵守目标仓库规则，避免改动其它会话的文件。未要求时不自行运行全量测试或扩大检查范围。
