# Rust 计划的调度覆盖

## 会话滚动并发覆盖

本节仅在计划含 Rust/Cargo 任务时加载，覆盖主技能默认的 5 会话滚动并发规则；实现与回归阶段均适用。

- 纯 Rust 批次最多 3 个活动任务会话；涉及 Rust 的混合语言任务也计入 Rust 配额。
- 混合批次总活动会话最多 5 个，其中 Rust 最多 3 个；其它语言沿用主技能默认窗口。Rust 配额满时，可补入后续满足依赖的其它语言任务。
- 任一会话完成、进入待回归或暂不可运行时，立即补入依赖和配额均满足的任务，不等待整波结束；始终满足 `总活动会话数 <= 5` 和 `Rust 活动会话数 <= 3`。
- 会话并发与编译资源分开管理；Rust 高内存编译仍串行排队，10 个共享缓存槽位不放宽上述限制。

## 构建资源与验收

- Rust 原生 Cargo 验证使用仓库共享缓存池 `target/rust-slot-1` 至 `target/rust-slot-10`，最多 10 个；由原任务会话按任务文件核验槽位归属、双缓存路径、复用和退出清理，主会话不直接构建或操作锁。
- 同仓库大型 Cargo 编译串行排队并复用缓存；单次 Cargo 的 `-j 1` 无法限制其它会话的编译。不得用多个槽位同时重编同一大型 crate。
- 子任务内完成必要定向单元测试；公共整仓检查合并到统一回归执行一次，不因还有公共检查而将全部任务标待回归。未受后续改动影响的已通过单元测试不机械重跑。
- 编译取消或超时后，由原任务会话确认自有 Cargo/rustc 等进程退出，再释放槽位或重试；其它语言普通单元测试不套用 Rust 高内存编译限制。
